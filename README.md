# 中小学对话式单元测试卷生成系统（exam-agent）

教师用一句话描述出卷要求，系统完成需求理解、蓝图规划、命题、校验与版本管理；
后续阶段加入混合检索、多 Agent 审核、对话式局部修改和 PDF 导出。

## 定位

**教师参与审核的中小学对话式试卷编制助手**：覆盖一至七年级数学、三至七年级英语（建设中）。
系统负责生成、核对、修改和导出；每道题标注“被验证到什么程度”，无法自动核对的题交给老师确认，
而不是包装成“审核通过”。

## 当前进度：阶段六进行中（网页版已完成，可通过临时链接给面试官使用）；阶段一～五已完成

已实现：

- **需求理解**：自然语言 → 结构化 `ExamRequest`，并显式列出系统做的假设（如推断年级）。
- **蓝图规划**：产出双向细目表（题型 × 分值 × 知识点 × 难度 × 认知层次）。
- **命题**：按 slot 出题，题型 / 分值 / 知识点从蓝图复制，不信任 LLM 自报。
- **不变量校验 + 反馈返修**：题数、总分、题型覆盖、选择题格式等由纯 Python 裁决，
  违例以具体中文说明反馈给 LLM；命题阶段只返修出错的题，合格的题直接保留。
- **版本存储**：SQLite 保存不可变版本快照，乐观并发检查防止覆盖。
- **运行轨迹**：每次 LLM 调用的耗时、token、校验结果写入 `trace_events`。
- **离线测试**：`ScriptedLLM` 回放预设回复，测试不花钱、结果可复现。

### 阶段二新增

- **对话模式** `python -m exam_agent chat`：在一个窗口里先出卷、再连续修改。
- **修改规划 Agent**：把“第 3 题太难，换一道基础题”翻译成结构化操作
  （rewrite / retype / add / remove / rescore / set_total / add_constraint），只决定“改什么”。
- **确定性执行**：题号先解析成稳定的 slot_id，再改蓝图、按题型重新编号、由求解器重配分值。
  试运行发现问题（题号不存在、删掉了老师要求的题型、凑不出满分）会反馈给规划 Agent 重新规划。
- **局部重出**：只有被修改的 slot 交给命题 Agent；即使命题 Agent 多返回了别的题，也会被丢弃。
- **一致性证明**：内容指纹比对，证明未被要求修改的题一个字都没变；分值因重配而变化时单独列出。
- **版本**：每次修改一个新版本，`/undo` 撤销也记为新版本（历史不改写），连续撤销可逐步回退；
  `diff` 命令比较任意两个版本。
- **上下文控制**：规划 Agent 只看数据库里当前版本的试卷摘要和最近 6 轮对话，不看完整解析。

### 阶段三新增

- **精确求解器**（`tools/linear.py`）：分数精确运算的线性方程（组）求解，12/7 不会变成 1.714；
  遇到非线性、条件不足等情况明确报告“不知道”，不给可疑结论。
- **盲解 Agent**：只看题干、看不到答案，独立列方程或选选项。它列出的方程交给求解器计算，
  得到与命题员无关的独立答案；觉得题干缺条件或有歧义时会报告。
- **教学审核 Agent**：只审新写的题，检查超纲、表述、蓝图符合度、重复；
  意见分 must_fix（触发返修）和 suggest（只告知老师），防止无限挑刺。
- **返修闭环**：只把有问题的题带着具体证据交回命题员；下一轮只审核返修过的题。
  停止条件：全部通过 / 达到 2 轮 / 问题题数没减少。没修好的问题如实展示，不隐藏。
- **约束回溯**：老师新增“计算题答案都要是整数”时，系统核验范围内所有现有题，只返修不符合的题，
  其余题的内容指纹保持不变。
- **命题时工具自查**：命题员为可求解的题附上方程，求解器当场验算，答案不符就带着正确值只重写这一题；
  配合“反向构造”（先定整数解再构造方程），从源头减少算错。独立审核仍然保留，用于发现建模和题意问题。
- **审核开关**：`--no-review` 关闭审核，用于后续对比实验。

示例：

```
老师> 出一份一元一次方程试卷，10 道题，选择、填空、计算都有，满分 100 分。
老师> 第 3 题太难，换一道基础题，其他题别动
老师> 增加一道应用题，仍然保持 10 题、100 分
老师> 计算题答案都要是整数
老师> 导出学生版和答案版
老师> /history
老师> /undo
```

### 阶段五新增：导出 PDF

- 对话中说“导出学生版和答案版”，或输入 `/export`，或运行 `python -m exam_agent export <paper_id>`。
- **学生版**：卷头（班级、姓名、学号）、按大题统计的得分表、分大题编排（如“一、选择题（本大题共 3 小题，每小题 5 分，共 15 分）”），
  选项按长度自动排成一行四个、两个或一个，计算题和应用题留出作答空白，一道题不会被拆到两页。
- **答案版**：每题附【答案】和【解析】，末尾附双向细目表；页脚标注试卷 id 和版本号，方便和数据库对应。
- 两份 PDF 都从数据库里同一个版本快照生成，题号、分值、内容必然一致。文件保存在 `output/` 文件夹。
- 使用 ReportLab（纯 Python），自动查找系统中文字体（Windows 宋体 / 黑体、macOS 华文黑体、Linux 文泉驿），
  也可用环境变量 `EXAM_PDF_FONT` 指定。补全了中文“避头点”规则，问号、逗号不会出现在行首。

### 验证路由与验证状态

每道题按形式选择核对工具，结果作为试卷状态的一部分随版本存入数据库：

| 状态 | 含义 | 典型题目 |
|---|---|---|
| 工具验证 | 工具独立算出答案，与给出的答案一致 | 口算、计算、解方程、能列式的应用题 |
| 独立复核一致 | 没有工具可用，但看不到答案的盲解 Agent 独立作答结果一致 | 概念选择题、填空题 |
| 待老师确认 | 没有任何手段能核对 | 看图题、说理题、开放题 |
| 存在未解决问题 | 返修后问题仍在 | — |
| 老师已确认 | 老师人工确认（原状态保留在说明里） | — |

- **路由顺序**：题干本身就是算式或方程时由代码直接提取（不经过模型，避免模型列错式）→ 盲解 Agent 列的方程 →
  盲解 Agent 列的算式 → 比对盲解答案 → 如实标记“待老师确认”。工具算不了就换下一条路，绝不据此下结论。
- **精确计算工具** `tools/arith.py`：分数精确运算（0.1 + 0.2 = 3/10）、百分数、有余数的除法（17 ÷ 5 = 3……2）。
- **相关错误**：命题员和盲解是同一个模型时，可能“两次答错得一样”（d019 统计表题、d024 阅读题两个答案）。对策：
  - 比较类选择题（哪组最多 / 最少）：盲解为每个选项列算式，程序精确计算后比较，不依赖模型选的字母；
  - 盲解作答后逐项排查其他选项是否也能成立，有多个答案即必须修改；
  - 盲解可以换用另一个模型：`.env` 中设置 `EXAM_BLIND_MODEL`（如 deepseek-v4-pro）或 `EXAM_BLIND_THINKING=enabled`，
    运行轨迹记录每一步实际用的模型。
- **老师确认**：对话中输入 `/confirm 3 7`，或运行 `python -m exam_agent confirm <paper_id> 3 7`；记为新版本，题目内容不变。
  `/verify` 或 `python -m exam_agent verify <paper_id>` 查看每题的验证情况；答案版 PDF 也标注每题的验证状态。
- **出卷范围严格按老师原话**：“三年级”是上下两册，“三年级上册”是上册，也可以具体到单元；不按日期推断。
  册别由代码对照老师原话核对，模型自行推断会被打回；年级写法（3年级、初一）和学段由代码统一。

### 阶段七：修改与讨论 Agent（ReAct）

老师不只是“改第几题”，还会按内容指代、追问细节、要求恢复旧版、让助手评价试卷。修改规划员改为 ReAct：
先按需查阅，再决定回答、追问还是提交修改方案。

- **只读工具**（DeepSeek 原生函数调用）：`get_question` 读全文、`search_questions` 全文搜索（原文包含优先，其余 BM25）、
  `paper_stats` 全卷统计（题型分值、难度、选择题答案分布、知识点重复、验证状态、英语短文词数）、
  `get_history` / `get_question_version` 版本历史、`lookup_scope` 查课程知识库判断是否超纲、
  `check_question` 程序核对（精确计算、英语语法级别与字数），最后 `submit_plan` 提交。
- **读写分离**：模型只能读；方案由 `apply_ops` 用代码校验和执行，不通过就把原因作为工具结果退回让模型修正。
- **新操作**：`restore` 只把一道题恢复成某个旧版本（不同于整卷撤销）；`patch` 局部改字（原文必须唯一定位，
  改后重新核验，答案不对就进入返修）。
- **讨论**：提问、评价时 `action=answer`，回答前必须读过相关题目；可以提出建议，老师同意后下一轮再执行。
- **停止条件**：最多 8 轮；同一工具同样参数重复调用视为原地打转；方案连续 3 次被退回则改为追问；到上限强制提交。
- **上下文控制**：一开始只给每题一行的索引，全文按需读取；最近 3 条工具结果保留全文，更早的压缩成一行摘要。
- **对比实验**：`python -m exam_agent eval-edit`，31 条标注指令（题号明确 / 按内容指代 / 局部改字 / 历史版本 /
  细节问答 / 全卷统计 / 超纲 / 讨论 / 应当追问 / 同意上一轮建议），比较一次调用（只看摘要）与 ReAct 的正确率、
  工具调用次数、token 和耗时。`EXAM_EDIT_PLANNER=oneshot` 可切回一次调用式规划。

### 端到端评测

`python -m exam_agent eval-e2e`：100 条老师的说法（数学 60、英语 25、边界 15，含应当拒绝的请求），
真实调用模型批量出卷；每份卷再由程序自动选两条修改指令（换题、改回原来的、扩大题数、提问、局部改字、加约束），
走完整流程并用代码检查结果。统计出卷成功率、正确拒绝率、修改成功率、题目验证状态分布、耗时与 token，
并导出随机抽样的题目表格供人工核对。支持并发（`--workers`）和中断续跑（`--resume`）。

### 阶段六：网页版

```powershell
pip install -r requirements.txt
python -m exam_agent web            # 浏览器打开 http://127.0.0.1:8000
```

- **界面**：左边对话（附示例句），右边试卷 / 蓝图 / 版本历史；每道题显示验证状态，可点“我已核对，确认”；
  下载学生版 / 答案版 PDF；撤销上一步。修改后，改动的题用黄色标出，其余题由内容指纹保证不变。
  右上角“新建试卷”清空页面重新出卷（已保存的试卷不删除）；“删除此试卷”“清空全部”会真正删除数据库中的试卷，
  删除前弹窗确认。命令行：`python -m exam_agent delete <paper_id>` / `delete --all`。
- **实时进度**：出卷要一两分钟，用 SSE 流式推送每一步（理解需求 → 检索知识库 → 规划 → 命题 → 盲解 → 审核 → 保存），
  重试时显示具体原因。
- **接口**：FastAPI，`/docs` 自动生成接口文档。业务逻辑在 `web/service.py`，不依赖 Web 框架，可直接测试。
- **并发与成本保护**：SQLite 连接加锁供多线程使用；同一份试卷的修改排队执行；每个 IP 每小时 30 次、同时最多 3 个出卷
  （环境变量 `EXAM_WEB_PER_HOUR`、`EXAM_WEB_CONCURRENCY`，设为 0 不限制）。

**给面试官使用（临时公开链接，不需要服务器）**：电脑上运行网页服务，再用 Cloudflare 免费隧道生成一个 https 链接：

```powershell
python -m exam_agent web                               # 终端 1
cloudflared tunnel --url http://localhost:8000         # 终端 2，输出 https://xxxx.trycloudflare.com
```

面试期间电脑保持开机、两个终端不要关。

- `cloudflared` 下载：https://github.com/cloudflare/cloudflared/releases （Windows 选 `cloudflared-windows-amd64.exe`，改名为 `cloudflared.exe`）。
  免费、不用注册，每次启动会生成一个新链接，面试前把链接发给面试官即可。
- 如果国内访问 trycloudflare.com 较慢，可以换用国内的内网穿透服务（如 cpolar），原理相同：把本机 8000 端口映射成一个公网地址。
- 现场面试直接用自己电脑的浏览器打开 http://127.0.0.1:8000 演示。
- 云端长期部署（简历上放一个常驻链接）可用仓库里的 `Dockerfile`。

### 小学数学知识库：半自动构建流水线

一至六年级 12 册、94 个单元，每个单元一张卡片（七年级上册按知识点细分）。不靠手写，也不完全交给模型：

| 步骤 | 谁做 | 命令 |
|---|---|---|
| ① 教材目录（只有单元标题） | 人工核对 | 编辑 `kb/math/sources/toc.json` |
| ② 骨架卡片：id、册别、全局顺序 | 代码 | `python -m exam_agent kb init` |
| ③ 起草：主要内容、不考什么、别名、信号词、课标依据 | 模型（每册一次调用） | `python -m exam_agent kb build [--books 三上,三下]` |
| ④ 校验：单元与目录一字不差、课标条目存在且学段匹配、信号词必须是新出现的术语 | 代码，不合格带具体问题让模型重写 | 随 build 自动执行 |
| ⑤ 抽检：随机抽取卡片生成核对表，填写对错 | 人工 | `kb sample --n 15` → `kb audit-report <核对表.csv>` |

抽检判为“对”的卡片标记为 `checked`，每次抽检的准确率追加到 `kb/math/audit/audit_history.csv`。
卡片状态：`skeleton`（只有目录）→ `draft`（模型起草）→ `checked`（人工核对）。目录据 AI 记忆整理，
人教版小学数学正在分年级换新版，**请按实际使用的教材核对 `toc.json`**。

### 检索接入出卷流程

1. **确定范围**：年级 + 册别按老师原话 → 若干册书；老师点名单元（“第二单元”）直接定位，点名知识点（“一元一次方程”）
   用检索在这几册里定位到单元。
2. **规划只能选候选知识点**：蓝图每道题必须填候选列表里的 `kp_id`，选了范围外的（如三年级卷选二年级单元）由代码打回。
3. **范围说明随蓝图保存**：所选卡片的主要内容和“不考什么”写进蓝图，命题和教学审核都按它判断，审核指出超纲时要写明依据。
4. **超纲信号词**：范围之后才出现的专有术语（如七上第五章卷里的“方程组”），题干一出现就由代码直接报告并返修。
5. `--no-kb` 关闭知识库，用于对比实验。知识库没覆盖的学科或年级如实说明，由模型判断范围。

### 英语（三至七年级）

- **题型按学科区分**：数学用选择、填空、计算、应用；英语用选择、填空、阅读理解、书面表达。规划出了不属于该学科的题型由代码打回。
- **知识库**：小学人教版 PEP 三至六年级 8 册、七年级 Go for it! 2 册，共 64 个单元。与数学共用同一条构建流水线，
  英语卡片多了“核心词汇”和“核心句型”两个字段，起草时代码校验词汇必须是小写英文、信号词必须是此前没出现过的英文词。
  `python -m exam_agent kb build --subject english`。
- **验证**：英语没有能“算出答案”的工具，所以如实分级——选择题、填空题比对盲解作答（一致为“独立复核一致”，
  填空不一致不判错，交给老师，因为可能有多个正确答案）；阅读理解逐个小题比对，不一致的小题指名报告；
  书面表达标为“待老师确认”。
- **年级适切性（规则由老师确定）**：
  - 语法严格：按《义务教育英语课程标准（2022年版）》分级硬性检查。一级（3～4 年级）一般现在时、现在进行时；
    二级（5～6 年级）加一般过去时、一般将来时、比较级；三级见附录 4。三年级卷出现过去时 → 必须修改。
    更细的“教材通常哪一册学”（如过去时在六下）只作提示。
  - 阅读短文长度在年级区间内：3～4 年级 50～200 词，5～6 年级 100～300 词，七年级 150～400 词；一份卷阅读篇数有上限。
  - 生词：不在课标词汇表中的词（小学对照二级词汇表 505 词，初中对照三级词汇表 1600 词；由 OCR 从课标 PDF 提取，
    见 `kb/english/standard/来源说明.md`）。阅读短文生词比例超过 15% → 必须修改；人名、数词、作答说明不计。
  - 在这些范围内偏难偏易由老师判断，直接在对话中说“第 20 题太难了，换一篇简单的”即可局部重出。
- **一二年级**：英语一般从三年级开设；且小学一二年级不进行纸笔考试，一二年级数学卷标题为“练习卷”。

### 阶段四：课程知识库与混合检索

已完成 4a～4c：知识库、检索器、检索评测。下一步 4d 把检索接入规划、命题、审核三个环节。

- **课程知识库** `kb/math/`：人教版（2024）七年级上册第一～五章的 36 个知识点卡片，另有 7 个后续年级内容
  （二元一次方程组、不等式、整式乘法、分式方程等），以及 15 条课标条目。每张卡片包含别名、考查边界（不考什么）、
  前置知识点和课标依据。内容由 AI 整理，**需人工核对**，清单见 `kb/math/核对清单.md`。
- **超纲是相对的**：知识点带全局顺序，相对于目标单元计算“本单元 / 前置（可用）/ 后续（超纲）”。
  同一个“去分母”，对第五章的卷子是本单元内容，对第四章的卷子就是超纲。
- **混合检索**：元数据硬过滤（年级、学科不交给相似度判断）→ BM25（字二元组分词，对错别字鲁棒）
  + 向量（本地 bge-small-zh-v1.5）→ RRF 按名次融合 → 交叉编码器重排（bge-reranker-base）。
  每条结果记录在各路检索中的名次，便于解释“为什么检索到它”。
- **本地模型**：用 fastembed（ONNX 推理，不需要 torch），首次使用自动下载到 `data/models/`，之后离线可用；
  文档向量缓存在 `data/emb_cache/`。也可在 `.env` 中设置 `EXAM_EMBEDDER=api` 改用 OpenAI 兼容的向量接口。
- **检索评测** `evals/retrieval_cases.jsonl`：63 条查询，分为术语原词、换说法/口语、错别字、出卷原话、超纲内容、
  课标条目六类；指标 Hit@1、Recall@3/5、MRR、延迟。

```powershell
python -m exam_agent kb check                              # 知识库完整性校验
python -m exam_agent kb show --unit 5                      # 查看第五章知识点
python -m exam_agent kb search "两辆车面对面开，多久碰头"     # 检索演示（显示各路名次）
python -m exam_agent eval-retrieval                        # 四种检索方式对比，结果存 evals/results/
python -m exam_agent eval-retrieval --embedder none        # 只评测 BM25（不需要模型）
```

### 审核效果对比实验

```powershell
python -m exam_agent eval-review --limit 10 --repeats 1   # 先用 10 题试跑
python -m exam_agent eval-review                          # 正式实验：40 题 × 4 种配置 × 3 次
```

- **数据集** `evals/review_cases.jsonl`：40 道七年级上册一元一次方程题，16 道正确、24 道各含一种已知缺陷
  （答案算错 8、列式错误 4、题干缺条件 4、选择题答案键错误 3、超出单元 3、情境不合常理 2），
  其中 3 道来自真实运行中出现过的错题。测试用求解器核验了标注本身。
- **四种配置**：仅格式校验 / 单模型带答案自查 / 盲解 + 求解器 / 盲解 + 求解器 + 教学审核。
- **指标**：检出率（按缺陷类别）、误报率、精确率、调用次数、token、耗时；每种配置重复 3 次取均值和范围。
- **结论**：见 `evals/EXPERIMENT_CONCLUSIONS.md`。完整审核检出率 100%、误报率 0%；
  “盲解 + 求解器”把算术错误检出率从单模型自查的 21%–38% 提高到 92%–96%。
- **结果保存**：每次运行生成 `review_eval_<时间>.json`（逐题原始数据）和 `.md`（报告），
  并在 `history.csv` 追加一行汇总，便于比较不同代码版本、不同模型的效果。
- 题目固定、不经过命题员，所以实验只衡量审核模块；改审核逻辑或换模型后重跑即可。

## 在 Windows + PyCharm 上运行

1. 安装 Python 3.11 或更高版本（安装时勾选 *Add python.exe to PATH*）。
2. PyCharm → **File → Open**，选择本项目文件夹。
3. **Settings → Project → Python Interpreter → Add Interpreter → Virtualenv**，
   在项目下新建 `.venv`。
4. 打开 PyCharm 底部的 **Terminal**（会自动激活 `.venv`），执行：

   ```powershell
   pip install -r requirements.txt
   pip install -e .
   ```

5. 复制 `.env.example` 为 `.env`，填入 DeepSeek API Key。
6. 检查连通性：

   ```powershell
   python -m exam_agent ping
   ```

7. 出第一份卷：

   ```powershell
   python -m exam_agent chat
   python -m exam_agent new "出一份一元一次方程试卷，10 道题，选择、填空、计算都有，满分 100 分。"
   python -m exam_agent show <paper_id> --answers --blueprint
   python -m exam_agent history <paper_id>
   python -m exam_agent trace <paper_id>
   python -m exam_agent export <paper_id>
   ```

8. 运行测试：`python -m pytest -q`，或在 PyCharm 中右键 `tests` 文件夹 → **Run 'pytest in tests'**。

> 如果终端中文乱码，先执行 `chcp 65001`，或在系统环境变量中设置 `PYTHONUTF8=1`。

## 关键设计取舍

| 问题 | 做法 | 原因 |
|---|---|---|
| 试卷真实状态放哪 | 数据库中的版本快照 | 语义记忆不可靠，不能作为唯一真相 |
| 分值由谁决定 | 蓝图决定，命题时复制 | 避免 LLM 自报分值导致总分漂移 |
| 校验失败怎么办 | 带具体违例反馈重试，最多 3 次 | 显式停止条件，失败可追踪 |
| 部分题目不合格 | 只返修不合格的 slot | 降低成本，也为局部修改打基础 |
| 版本快照 vs 逐题表 | 整卷快照 | 规模小、实现简单、天然支持回滚；规模变大后再拆表 |
| “第 3 题”指哪道 | 每次修改前按当前版本解析成 slot_id | 题号会因增删和改题型而变化，slot_id 永不变 |
| 分值怎么重配 | 求解器：总分正确、同类同分、改动最少 | 算术问题不交给模型 |
| 撤销怎么做 | 把旧内容提交为新版本 | 历史不可改写，撤销本身可追溯 |
| 怎么验证答案 | 命题时工具自查 + 独立盲解 + 精确求解器 | 自查便宜但只能查算术；盲解独立，能查建模和题意 |
| 审核发现错题后怎么修 | 退回命题员时附上求解器给的正确值 | 实测只说“答案错了”，返修后会写出另一道算错的题 |
| 为什么不用 SymPy | 自写线性求解器，接口可替换 | 当前范围是线性方程；无依赖、精确、可测试 |
| 审核会不会无限返修 | must_fix/suggest 分级 + 三种停止条件 | 有界成本，失败可解释 |
| 老师没让动的题 | 只做客观核验，不做教学挑刺 | 尊重老师意图，避免意外改动 |
| 超纲怎么判断 | 知识点全局顺序 + 相对目标单元计算 | 同一知识点对不同单元的卷子含义不同，不能存成固定标签 |
| 年级、学科怎么筛 | 检索前元数据硬过滤 | 硬条件不交给相似度“大概判断” |
| 两路检索怎么合并 | RRF 只看名次 | BM25 分数和余弦相似度量纲不同，直接相加没有意义 |
| 中文怎么分词 | 字二元组，不用 jieba | 错别字、教学术语不会因切错词而完全匹配不上；无依赖、结果确定 |
| 向量模型放哪 | 本地 fastembed（ONNX），接口可换 API | 免费、离线、实验可复现；不需要 torch，部署镜像小 |
| 不能自动核对的题怎么办 | 标为“待老师确认”，老师可人工确认 | 无法验证是正常结果，不能包装成“审核通过” |
| 出卷范围谁决定 | 老师原话；代码核对册别 | 不替老师猜，同一句话任何时候出卷范围都一样，测试可复现 |
| 小学知识库怎么建 | 目录人工核对，模型起草，代码校验，人工抽检 | 事实骨架（有哪些单元、先后顺序）不交给模型；模型只做概括，质量用抽检准确率衡量 |
| 怎么防止考低年级内容 | 规划只能选范围内的卡片 id，代码校验 | 实测无知识库时三年级卷有约三分之一的题是二年级内容（d018） |
| 英语题怎么验证 | 比对盲解作答，写作交给老师 | 没有能算出答案的工具，就不假装验证；填空不一致不判错，避免误报 |
| 盲解和命题员用不用同一个模型 | 默认相同，可单独配置 | 同一模型会犯相同的错；换模型的收益和成本用审核对比实验衡量 |
| 英语怎么判超纲 | 语法按课标分级硬性检查，阅读按年级控制难度，单词只计入生词率 | 老师指出英语允许个别生词；按单词判超纲导致无效返修（d021） |
| 哪里让模型自己选工具 | 只在修改与讨论（ReAct）；出卷和验证路由由代码编排 | 老师的说法千变万化，要查什么无法事先确定；验证要求可靠，路由写死更稳 |
| ReAct 能不能直接改卷 | 不能：工具只读，方案经代码校验后执行 | 模型负责理解，代码负责一致性（题数、总分、版本） |
| “改回原来的”怎么做 | 查版本历史找到该题内容变化前的版本，单题恢复 | 整卷撤销会连带丢掉其他题后来的修改 |
| PDF 用什么生成 | ReportLab | 纯 Python、无需安装外部排版程序，部署简单；代价是数学公式只能以纯文本显示 |
