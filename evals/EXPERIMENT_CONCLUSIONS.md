# 审核效果对比实验：结论

> 实验时间：2026-10-16（实验 1）、2026-10-23（实验 2）
> 模型：`deepseek-flash`（非思考模式）
> 原始数据：`evals/results/review_eval_20261016_204120.*`、`evals/results/review_eval_20261023_162558.*`

## 一句话结论

**让模型只列方程、由精确求解器负责计算，再配合教学审核，能在不增加误报的前提下发现全部缺陷；
单靠模型自己检查，会漏掉大部分算术错误。**

## 实验在问什么

出卷系统需要审核环节来拦截错题。审核有不同做法，成本也不同。实验要回答三个问题：

1. 让模型带着答案自己检查，够不够用？
2. “盲解 Agent + 求解器”这套设计，到底比自查好在哪里？
3. 教学审核值不值得多花一倍的成本？

## 实验设计

- **数据集**：40 道七年级上册一元一次方程题，16 道完全正确，24 道各含一种已知缺陷。

  | 缺陷类别 | 题数 | 例子 |
  | --- | --- | --- |
  | 答案算错 | 8 | 相遇时间应为 12/7 小时，答案写 1.5 小时 |
  | 列式错误 | 4 | 相向而行误用速度差 |
  | 题干缺条件或有歧义 | 4 | 说“检验下列各数”却没给出任何数 |
  | 选择题答案键错误 | 3 | 解析算出选 C，答案却标 B |
  | 超出本单元 | 3 | 一元二次方程出现在一元一次方程单元 |
  | 情境不合常理 | 2 | 女生人数算出 18.5 人 |

  其中 3 道取自系统真实运行时出过的错题。所有标注都经求解器核验。

- **四种审核方式**：

  | 配置 | 做法 |
  | --- | --- |
  | 仅格式校验 | 只检查选项数量、答案格式等，不调用模型（基线） |
  | 单模型自查 | 一个模型同时看到题目、答案和解析，找出有问题的题 |
  | 盲解 + 求解器 | 盲解 Agent 看不到答案，独立列方程；求解器精确计算后与答案比对 |
  | 完整审核 | 盲解 + 求解器，再加教学审核 Agent（检查超纲、表述、重复） |

- **重复**：每种方式跑 3 次，取平均值和范围。模型每次输出不同，只跑一次不可靠。

## 结果（实验 2，最终版本）

| 配置 | 检出率 | 误报率 | token / 40 题 | 耗时 / 40 题 |
| --- | --- | --- | --- | --- |
| 仅格式校验 | 0% | 0% | 0 | 0 秒 |
| 单模型自查 | 78% | 2% | 4081 | 8 秒 |
| 盲解 + 求解器 | 83% | 0% | 5486 | 10 秒 |
| **完整审核** | **100%** | **0%** | 9652 | 17 秒 |

各类缺陷的检出率：

| 缺陷类别 | 单模型自查 | 盲解 + 求解器 | 完整审核 |
| --- | --- | --- | --- |
| 答案算错 | 38% | 96% | 100% |
| 列式错误 | 100% | 100% | 100% |
| 题干缺条件或有歧义 | 92% | 100% | 100% |
| 选择题答案键错误 | 100% | 100% | 100% |
| 超出本单元 | 100% | 0% | 100% |
| 情境不合常理 | 100% | 67% | 100% |

> 检出率：有缺陷的题中被发现的比例，越高越好。
> 误报率：正确的题中被错误标记的比例，越低越好。误报会触发不必要的返修，可能把好题改坏。

## 结论

### 结论 1：模型带着答案自查，抓不住算术错误

8 道算错的题，单模型自查在实验 1 中只抓到 21%，实验 2 中是 38%。真实运行中出过的两道错题
（40/7 写成 41/8、12/7 写成 1.5）多次被放过。

但自查对语义类问题很敏锐：列式错误、超纲、情境不合常理都是 100%。所以它的问题不是“不会检查”，
而是**看到答案后会顺着答案去理解，很难发现计算上的偏差**。

### 结论 2：模型会列方程，但不会算；计算必须交给工具

这是实验中最直接的证据。盲解 Agent 对 w02（正确答案 40/7）的 6 次独立作答：

| | 6 次运行的结果 |
| --- | --- |
| 盲解 Agent 自己算出的答案 | 35/8、35/8、37/8、37/8、79/14、41/8（**全部错误**） |
| 求解器按它列出的方程算出的答案 | 40/7（**6 次全部正确**） |

正确题 c11 也一样：盲解 Agent 自己算出过 -1、-5、5 等错误答案，但系统只比对求解器的结果，
所以没有误报。

如果直接比对模型自己算的答案，不仅会漏掉错题，还会冤枉正确的题。**“模型负责理解题意、列方程，
求解器负责计算”这种分工，是盲解 + 求解器能把算术错误检出率提到 92%–96% 且零误报的原因。**

### 结论 3：盲解 + 求解器与教学审核分工互补，缺一不可

- 盲解 + 求解器只关心“算得对不对”，所以对超纲题的检出率是 **0%**：一元二次方程它也能正确求解，
  但不会意识到这道题不该出现在一元一次方程单元。
- 教学审核补上了这一块：加入后超纲题检出率达到 **100%**。
- 反过来，教学审核不做验算，算术错误要靠求解器。

两者组合后，6 类缺陷全部达到 100%。

### 结论 4：完整审核的代价是成本翻倍，但换来了零漏报、零误报

完整审核的 token 消耗约为单模型自查的 **2.4 倍**，耗时约 2 倍。按 deepseek-flash 的价格，
审核 40 道题大约花几分钱，对出卷场景完全可以接受。

如果对成本敏感，只用盲解 + 求解器也能拦住几乎所有客观错误（83%，零误报），只是会漏掉超纲题。

### 结论 5：评测方法本身也可能出错

实验 1 中完整审核的误报率是 8%。逐条查看误报理由后发现，4 次误报中有 3 次的理由是
“与同批另一题重复”。原因是实验把考同一知识点的题拼进了同一份“试卷”，人为制造了重复。

修正分组方式并加入测试后，实验 2 的误报率降为 0%。剩下那 1 次误报（模型看错了选项）
在实验 2 中没有复现，说明真实误报存在但频率很低。

**这次误报率的下降来自修正实验，而不是改进系统。** 不逐条分析误报理由，就会把评测的问题
误当成系统的问题。

## 两次实验对比

| 指标 | 实验 1 | 实验 2 | 说明 |
| --- | --- | --- | --- |
| 自查：算术错误检出率 | 21% | 38% | 两次都远低于盲解 + 求解器 |
| 盲解 + 求解器：算术错误检出率 | 92% | 96% | 稳定 |
| 盲解 + 求解器：总检出率 | 85% | 83% | 稳定 |
| 完整审核：检出率 | 100% | 100% | 稳定 |
| 完整审核：误报率 | 8% | 0% | 修正评测分组后下降 |

核心结论在两次实验中一致，可信度高于单次结果。

## 对系统设计的影响

| 实验发现 | 设计决策 |
| --- | --- |
| 模型算术不可靠 | 所有计算交给精确求解器，模型只列方程 |
| 看到答案的模型会被答案带偏 | 盲解 Agent 看不到答案（信息隔离） |
| 盲解 + 求解器管不了超纲 | 保留教学审核，两者分工 |
| 教学审核偶尔误判 | 意见分 must_fix / suggest 两级，只有前者触发返修 |
| 盲解 Agent 偶尔漏写方程（w01 漏报 1 次） | 待做：题干为“解方程：……”时由代码直接提取方程 |

## 局限

- 数据集只有 40 题，由作者构造，只覆盖一个年级的一个单元；正确题只有 16 道，误报率的波动范围较大。
- 列式错误题的解析里直接写出了错误方程，比真实情况更容易被发现，可能高估了自查在这一类上的表现。
- 只测试了 deepseek-flash 一个模型的非思考模式。
- 实验衡量的是审核模块对固定题目的判断能力，不是端到端出卷质量。

## 可用于简历的表述

- 设计“盲解 Agent + 精确求解器”的信息隔离审核机制，由模型列方程、求解器负责计算。在 40 题标注集上，
  答案计算错误检出率由单模型自查的 21%–38% 提升至 92%–96%（两轮实验，各重复 3 次），零误报。
- 通过消融实验确定审核组合，缺陷检出率 100%、误报率 0%，token 成本约为单模型自查的 2.4 倍；
  通过逐条误报归因，发现 3/4 的误报来自评测分组偏差，修正评测方法并加入回归测试。
